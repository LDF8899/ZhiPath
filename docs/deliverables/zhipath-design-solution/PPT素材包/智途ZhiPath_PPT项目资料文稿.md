## 一、项目基础信息

### 1. 项目名称

- 中文名称：智途
- 英文名称：ZhiPath
- 项目副标题：岗位驱动的多智能体职业学习与能力成长平台
- 推荐口号：让每一次学习，都成为可验证的职业能力

### 2. 一句话介绍

智途 ZhiPath 以真实岗位要求为目标，以多智能体生成学习资源，以 Git 思想记录能力演进，把“岗位分析、学习规划、过程评价、技能画像和简历生成”连接成可追踪、可比较、可回溯的成长闭环。

### 3. 项目关键词

`岗位驱动`、`多智能体`、`Git 学习模型`、`能力证据链`、`六因子岗位匹配`、`智能简历`、`多模态资源`、`学习数字孪生`

### 4. 项目定位

智途不是单纯的课程平台，也不是在页面上增加一个聊天机器人。系统将招聘岗位视为动态目标，将学习任务视为行动，将考试、项目和资源完成情况视为证据，将技能快照视为能力状态，最终把成长成果转化为岗位匹配结果和可投递简历。

## 第 2 页：项目摘要

### 屏幕正文

**从岗位目标出发，形成完整成长闭环**

1. 解析岗位，明确真实能力要求
2. 识别差距，生成主线与支线计划

4. 统一评价，沉淀可验证能力证据

### 讲解备注

## 第 3 页：项目背景

### 屏幕正文

**生成式 AI 降低了知识获取成本，却没有自动解决职业成长问题**

- 招聘 JD 更新快，课程内容与岗位需求存在时间差
- 学生同时面对课程、项目、考试和求职，多条任务线容易失序
- 通用 AI 能回答问题，但缺少长期画像、业务状态和证据沉淀
- 学习结果常被压缩为“进度百分比”，难以证明真实能力提升

### 讲解备注

同一个“前端工程师”岗位，在不同企业可能同时要求 React、TypeScript、工程化、性能优化、跨端能力和业务理解。如果学习路径仍然只按教材目录排列，学生即使完成课程，也很难知道自己距离岗位还有多远。另一方面，直接让大模型生成计划又容易一次性、不可追踪，甚至出现事实与来源混淆。

## 第 4 页：用户痛点

### 屏幕正文

| 痛点 | 用户真实问题 | 智途应对方式 |
| --- | --- | --- |
| 目标模糊 | “我要学前端，但先学什么？” | 将岗位要求转化为能力目标 |
| 计划混乱 | 必修与兴趣内容混在一起 | main 主线与 side 支线分离 |
| 过程不可追踪 | 学完后只剩完成百分比 | Commit、Snapshot、Delta |
| 评价碎片化 | 考试、项目、速测互不相通 | 统一评价主线与证据链 |
| 来源不透明 | AI 推荐被误认为真实招聘 | 标注 web / ai_generated |
| 表达断裂 | 学习成果无法写入简历 | 证据驱动的岗位定制简历 |

### 讲解备注

这些问题并不是六个孤立功能，而是一条链上的断点。智途的设计原则是：先建立可计算的岗位目标，再组织学习投入；每一次学习都留下证据，每一次能力变化都能回溯到具体行动。

## 第 5 页：产品定位与用户角色

### 屏幕正文

**核心用户**

- 高校学生：从职业方向探索到求职准备
- 转岗与初职学习者：围绕目标岗位补齐能力差距
- 教师与辅导者：观察学习过程、能力变化和评价结果
- 学校与管理人员：维护岗位、考试和运营数据

**产品边界**

- AI 负责分析、生成、整理与建议
- 用户负责目标确认、证据提交和最终决策
- 系统负责权限校验、状态管理与操作留痕

### 讲解备注

系统把 AI 定位为受业务规则约束的协作者，而不是拥有无限权限的代理。模型不能直接伪造技能、项目、招聘状态和学习完成记录；具有业务后果的动作必须由后端校验，并留下用户、时间、动作和证据。

## 第 6 页：核心解决方案

### 屏幕正文

**岗位 → 差距 → 计划 → 学习 → 评价 → 能力 → 简历**

- 岗位是目标，不是静态信息卡片
- 计划是资源与时间的调度器，不是一次性清单
- 评价是能力更新依据，不是孤立分数
- 简历是成长证据的表达层，不是凭空生成的文案

### 讲解备注

智途使用统一的业务闭环把多个模块连接起来。用户选择岗位后，系统计算六因子匹配与技能差距，生成岗位主线；学习动作产生提交和技能快照；考试、速测与项目评价写入证据链；最终简历智能体只基于已有事实组织表达。

## 第 9 页：总体技术架构

### 屏幕正文

**表现层**：React 19、TypeScript、Vite、Three.js  
**业务层**：NestJS、TypeORM、JWT、SSE / WebSocket  
**智能层**：LangGraph、DeepSeek、多专业智能体  
**任务层**：BullMQ、Redis、异步任务与状态广播  
**数据层**：MySQL、MongoDB、Neo4j、Chroma、MinIO  
**搜索层**：search-proxy、SearXNG、Browserless、Redis

### 讲解备注

前端负责交互与可视化，NestJS 承担业务事务和权限边界，LangGraph 负责编排多步骤智能体，BullMQ 将视频和资源生成等长任务异步化。核心业务以 MySQL 为事实源，其余数据组件按场景逐步启用；外部模型与搜索服务均通过适配器隔离。

## 第 11 页：多智能体协作引擎

### 屏幕正文

**统一编排、专业执行、资源落账**

- Orchestrator：理解目标、拆解任务、选择动作
- ProfileAgent：整理画像与技能证据
- PathAgent：生成或调整学习路径
- Lecture / Code / Reading / Exam Agent：生产专业资源
- ReviewerAgent：审校生成内容
- JdParserAgent：提取结构化岗位信息
- ResumeAgent：生成岗位定制简历
- VideoAgent：组织脚本、语音与教学视频

### 讲解备注

对话入口先由意图路由判断场景，LangGraph 保存消息、动作、资源和错误状态，再由动作执行器调用专业服务。结果统一写入资源台账，因此用户切换页面或恢复会话后仍能找到生成内容，而不是让重要结果只停留在一段聊天记录里。

## 第 12 页：智能体状态机与容错

### 屏幕正文

1. 识别意图与当前页面场景
2. 生成可执行动作序列
3. 调用专业服务或进入异步队列
4. 审校并结构化输出
5. 写入资源台账并广播状态
6. 失败时保留局部结果并允许重试

### 讲解备注

LangGraph 使用显式 State 保存消息、意图、动作、资源和错误。条件边决定继续执行、请求澄清或结束。外部服务失败时不会丢弃已经完成的局部结果；长任务经 BullMQ 排队，并通过 SSE 更新智能体办公室的运行状态。模型 JSON 还要经过提取、修复与字段校验，避免代码块包装、截断或字段漂移直接进入业务数据库。

## 第 13 页：岗位 JD 获取方案

### 屏幕正文

**本地岗位库 + 联网搜索 + 透明降级**

- 本地模式：对标题、公司、城市、JD 与技能进行结构化检索
- 联网模式：SearXNG 聚合国内可访问搜索引擎
- 页面抓取：Browserless 获取动态网页正文
- 信息提取：LLM 将非结构化文本转换为岗位字段
- 降级策略：联网失败时可给出 AI 方向建议，但必须明确标记

### 讲解备注

系统将联网能力独立为 search-stack。SearXNG 负责候选结果，Browserless 负责动态网页，搜索代理统一缓存、限流和内容提取。针对中国境内网络环境，配置百度、Bing、360、搜狗等可访问引擎，并设置国内 DNS。外部搜索失败不会拖垮核心岗位库。

## 第 14 页：岗位来源透明设计

### 屏幕正文

| 来源状态 | 页面标识 | 用户操作 |
| --- | --- | --- |
| `local` | 平台岗位 | 查看内部详情与匹配结果 |
| `web` | 联网岗位 | 查看摘要并跳转原始来源 |
| `ai_generated` | AI 推荐 | 仅作方向参考，不伪装真实招聘 |

**设计原则：技术降级必须转化为明确业务状态。**

### 讲解备注

很多联网功能在失败后仍显示“联网结果”，这会误导用户。智途为岗位卡片增加来源字段，真实网页保留 URL 和 host；模型补充内容显示“AI 推荐”，详情页提示“不代表企业当前正在招聘”，同时隐藏无效投递动作。

## 第 15 页：六因子岗位匹配

### 屏幕正文

**六类证据共同形成岗位匹配结果**

- 必须技能：岗位硬性能力是否满足
- 加分技能：竞争力与技术广度
- 项目经历：是否有场景化实践证据
- 考试成绩：基础知识与专项能力验证
- 学习进度：当前成长状态与完成质量
- 学习速度：达到投递门槛的时间趋势

输出不只有总分，还包括 `matched`、`missing`、`gapAnalysis`、分项得分和 `canApply`。

### 讲解备注

系统根据校招和社招场景调整权重：校招更关注考试与学习证据，社招提高项目经历和必须技能权重。总分只负责概括，真正指导行动的是已匹配技能、缺失技能和可投递门槛。

## 第 16 页：Git 思想驱动的学习模型

### 屏幕正文

| Git 概念 | 学习语义 |
| --- | --- |
| Branch | 一条独立学习目标线 |
| Commit | 一次有证据、可解释的学习动作 |
| Snapshot | 提交后的完整能力状态 |
| Delta | 前后能力变化 |
| Compare | 分支或快照差异 |
| Merge | 将支线成果并入岗位主线 |
| Rollback | 非破坏式回到历史能力状态 |

### 讲解备注

传统学习平台通常只有线性进度条，难以表达目标切换、兴趣探索和能力回溯。智途借鉴 Git：岗位目标对应 main 主线，兴趣与补充技能对应 side 支线；每次学习形成 commit，每个 commit 关联能力快照，支线成果经过比较后可合并到主线。

## 第 17 页：主线与支线计划

### 屏幕正文

**Main 主线**

- 由目标岗位和能力差距驱动
- 同一时间只保留一个 active 主线
- 获得稳定、优先的每日工时预算
- 关注投递门槛和关键能力达成

**Side 支线**

- 由兴趣、临时需求和补充技能驱动
- 可同时存在多条，独立推进
- 不污染岗位主线完成度
- 成果可比较、合并或归档

### 讲解备注

这套模型解决“额外想学的内容应该放在哪里”的业务冲突。每日时间由 `dailyHours` 和 `mainRatio` 分配，主线优先保持连续性；自选内容只能进入支线，避免兴趣任务把岗位达成进度冲散。

## 第 18 页：统一评价证据链

### 屏幕正文

**Attempt → Result → DimensionScore → Evidence → Impact**

- Attempt：一次评价会话
- Result：总分、结论与评价状态
- DimensionScore：分维度能力表现
- Evidence：答案、代码、项目或任务证据
- Impact：本次评价如何影响技能、计划与岗位匹配

### 讲解备注

考试、快速测验、AI 评估、任务完成和错题复习不再各自保存一套互不相通的结果。统一评价模型使“为什么某项技能提升了”“哪一次考试影响了岗位匹配”可以沿证据链回溯。完成评价后还能生成学习 commit 和新的技能快照。

## 第 19 页：能力画像与可视化

### 屏幕正文

**技能事实 + 能力维度 + 历史快照**

- 技能清单回答“会什么、掌握到什么程度”

## 第 28 页：可靠性、安全与可观测性

### 屏幕正文

**可靠性**：缓存、限流、超时、重试、局部结果保留  
**安全性**：JWT、角色守卫、输入校验、密钥环境变量化  
**事实约束**：来源标注、结构校验、人工确认、禁止虚构  
**可观测性**：任务状态、SSE 事件、错误记录、资源台账  
**可降级性**：外部 AI、搜索和地图失败不阻断核心本地功能

### 讲解备注

搜索、模型、地图与语音服务都属于外部依赖，必须假设它们可能超时或失效。系统通过适配器、缓存、降级和明确状态隔离风险。生产化阶段还需要继续完善密钥轮换、最小权限、岗位失效扫描、队列监控、数据脱敏和外部服务熔断。

## 五、产品现场演示脚本

### 演示路线 A：完整业务闭环（约 4 分钟）

1. 打开学生首页，说明今日任务、目标岗位和成长状态。
2. 进入岗位页，切换本地、混合和联网模式，强调来源标识。

### 演示路线 B：突出 AI 能力（约 3 分钟）

1. 在 AI 助教中提出一个岗位学习目标。
2. 展示意图识别和专业智能体调度。
3. 打开资源台账，展示讲义、代码、图解或视频资源。
4. 展示“记忆工程流程图”多模态案例。
5. 展示“Docker 视频 + 专项计划”联动案例。
6. 回到学习页说明资源如何进入任务、评价和能力更新。

- 始终说明 AI 推荐与真实联网岗位的区别。

## 六、评委常见问题与参考回答

### Q1：这个项目和普通 AI 学习助手有什么区别？

普通 AI 助手的核心产物是一次回答，智途的核心产物是持续演进的业务状态。岗位目标、学习计划、生成资源、评价证据、技能快照和简历版本都进入数据库并相互关联，用户可以比较、回溯、合并和恢复，而不是依赖聊天上下文。

### Q2：为什么要引入 Git 思想？会不会增加用户理解成本？

Git 提供了一套成熟的“多目标并行、历史可追踪、变化可比较、成果可合并”模型，正好对应岗位主线和兴趣支线的冲突。界面使用“主线、支线、学习提交、能力快照”等自然语言，Git 术语主要作为底层模型和可视化隐喻，不要求普通用户掌握代码版本控制。

### Q3：岗位匹配分数可靠吗？

系统不会把总分作为唯一判断，而是展示六个因子的分项贡献、已匹配技能、缺失技能和投递门槛。当前模型主要用于解释和行动建议，未来会用真实投递结果、岗位族和技能本体进行校准。联网岗位还保留原始来源，用户可以核对事实。

### Q4：如何避免大模型幻觉？

第一，真实岗位与 AI 补充内容使用不同来源状态；第二，模型输出必须经过结构提取和字段校验；第三，技能、项目和学习完成记录只能由业务服务更新；第四，简历禁止补造缺失经历；第五，重要操作由用户确认，并保留证据和审计信息。

### Q5：多智能体是否只是把一个提示词拆成多个角色？

不是。每个智能体对应明确业务输入与输出，编排层保存状态，动作执行器调用真实服务，长任务进入队列，结果写入统一资源台账。即使用户切换页面或任务部分失败，已完成资源仍然存在，这与单轮角色扮演式提示词有本质区别。

### Q6：系统如何处理联网搜索失败？

优先返回本地结构化岗位；联网模式通过 search-stack 调用 SearXNG 和 Browserless，并使用缓存、限流和超时控制。如果真实搜索失败，可以提供明确标记的 AI 方向建议，但不会伪装成当前招聘岗位，也不会提供无效投递按钮。

### Q7：技能掌握度由谁决定？

技能掌握度来自多种证据，包括正式考试、快速测验、项目和代码评价、任务完成以及用户确认。统一评价主线记录 Result、DimensionScore、Evidence 和 Impact，技能变化再绑定到 commit 和 snapshot，避免仅由模型主观修改一个数值。

### Q8：为什么同时使用二维雷达和三维图谱？

二维雷达适合稳定比较固定维度，用户能快速看出能力结构变化；三维图谱适合探索技能节点之间的关系和类别分布。两者承担不同的信息任务，三维图不是为了替代所有数据表格。

### Q9：项目当前完成度如何？

项目已完成学生端、管理端、NestJS 后端、MySQL 核心数据、多智能体编排和 search-stack 集成。后端 12 个测试套件、37 项测试通过，前后端构建通过，14 个核心页面已使用真实 Edge 浏览器回归并完成截图，控制台错误为 0。

### Q10：下一阶段最重要的工作是什么？

优先提高真实岗位数据覆盖和时效性，完善匹配权重校准、代码沙箱和评价 Rubric，同时加强密钥轮换、队列监控、数据脱敏和内容引用治理。这些工作比继续增加表面 AI 功能更能提升系统可信度。

### Q11：商业或推广价值是什么？

面向个人可以提供岗位成长订阅与高级简历服务；面向学校可以提供专业培养与就业能力分析；面向企业可以提供实习岗位、技能标准和候选人成长证据对接。项目早期应先通过学校和学生场景验证闭环，再拓展校企合作。

### Q12：数据安全如何保证？

当前系统使用 JWT 和角色守卫隔离学生与管理端，外部密钥通过环境变量配置，关键写操作由服务层校验。生产化需要进一步实施最小权限、密钥轮换、敏感字段加密与脱敏、审计日志、备份恢复和数据保留周期管理。

## 七、可直接用于宣传或申报的项目简介

### 100 字简介

智途 ZhiPath 是一款岗位驱动的多智能体职业学习平台。系统将真实岗位需求转化为主线学习目标，以 Git 分支思想管理岗位学习与个人兴趣，通过考试、项目和任务沉淀能力证据，并据此生成技能画像、岗位匹配分析和定制简历，让学习过程可追踪、能力变化可解释、求职成果可验证。

### 300 字简介

智途 ZhiPath 面向高校学生和初入职场学习者，针对职业目标模糊、学习计划混乱、评价结果碎片化以及学习成果难以转化为求职竞争力等问题，构建岗位驱动的多智能体职业成长平台。系统通过本地岗位库、SearXNG 联网检索和 Browserless 网页抓取获取岗位信息，并使用六因子模型分析必须技能、加分技能、项目经历、考试成绩、学习进度和学习速度。学习侧借鉴 Git 思想，将岗位目标定义为 main 主线，将兴趣和补充技能定义为 side 支线，以 Commit、Snapshot、Delta、Compare、Merge 和 Rollback 记录能力演进。LangGraph 编排画像、路径、讲义、代码、考试、岗位解析、简历和视频等专业智能体，生成结果统一进入资源台账和学习计划。统一评价主线将考试、速测、AI 评价、错题和任务证据连接到技能画像与岗位匹配，最终生成基于真实事实的岗位定制简历。项目已完成学生端、管理端、搜索栈和多智能体服务集成，具备完整可运行形态。

### 800 字项目说明

随着生成式人工智能快速普及，知识解释和内容生成的成本显著降低，但学生的职业成长仍面临目标不明确、学习内容与岗位脱节、多条任务线难以协调、评价证据分散以及成果表达不足等问题。传统课程平台围绕固定章节组织内容，题库平台主要记录答题分数，招聘平台聚焦岗位推荐与投递，通用 AI 助手则缺少长期画像、业务状态和可审计动作。这些能力之间缺乏连接，使学生即使投入大量时间，也难以回答“距离目标岗位还有多远”。

智途 ZhiPath 将岗位数据视为动态目标，将用户技能、项目、考试和学习提交视为能力证据。系统从岗位搜索与 JD 解析开始，通过六因子模型分析必须技能、加分技能、项目经历、考试成绩、学习进度和学习速度，形成可解释的岗位差距与投递门槛。针对岗位必修内容和个人兴趣之间的冲突，项目借鉴 Git 版本控制思想：目标岗位对应 main 主线，兴趣探索和补充技能对应 side 支线；每次学习动作形成 Commit，提交后的能力状态形成 Snapshot，前后变化形成 Delta，支线成果可以 Compare、Merge，也能以非破坏方式 Rollback。该模型让成长过程具备分支化、版本化和可回溯能力。

在智能能力方面，项目使用 LangGraph 构建多智能体状态机，由统一编排器协调画像、学习路径、讲义、代码、阅读、考试、审校、岗位解析、简历和视频等专业智能体。长任务通过 BullMQ 与 Redis 排队，运行状态通过 SSE 广播，生成内容统一写入资源台账，因此资源不会因页面切换或会话结束而丢失。系统支持 Markdown 讲义、技术图解、代码练习、延伸阅读、考试、错题解析和教学视频等多模态内容，并能将资源直接关联到学习计划和后续评价。

评价层通过 Attempt、Result、DimensionScore、Evidence 和 Impact 统一正式考试、快速测验、AI 评估、任务完成和错题复习。每次评价不仅产生分数，还记录证据以及对技能、计划和岗位匹配的影响，再生成新的学习提交和能力快照。画像页面同时提供固定维度雷达与可交互三维技能图谱：二维视图用于稳定比较，三维视图用于理解技能节点和关系。简历智能体基于画像、项目、教育信息和目标岗位生成结构化版本，禁止虚构缺失经历，并提供人工编辑、分支版本与 PDF 导出。

项目采用 React、TypeScript、Vite、Three.js 构建前端，以 NestJS、TypeORM 和 MySQL 承担业务事务，通过 SearXNG、Browserless、Redis 构成联网岗位搜索栈。系统明确区分本地岗位、真实联网岗位和 AI 推荐，真实结果保留来源 URL，AI 内容不伪装成企业当前招聘。当前版本已完成学生端、管理端、搜索栈和多智能体模块联调，12 个后端测试套件、37 项测试通过，前后端构建通过，14 个核心页面完成真实浏览器回归且控制台错误为 0。智途希望把一次性的 AI 问答升级为可持续演进的职业成长基础设施，让每一次学习都成为可验证、可复用的能力证据。

## 十、PPT 排版建议

### 页面比例与网格

- 使用 16:9，推荐 1920×1080。
- 标题区约占页面高度 12%，正文区约占 78%，页码与来源区约占 10%。
- 截图页优先使用 60%～75% 页面宽度展示产品，不要裁掉侧边导航和关键状态。
- 架构图保持原始宽高比，不拉伸，不叠加大段文字。

### 文字层级

- 页面标题：28～34 pt。
- 核心结论：20～24 pt。
- 正文：16～20 pt。
- 图注与来源：11～14 pt。
- 一页只保留一个结论，正文尽量不超过 6 条。

### 配色建议

- 延续项目现有的克制蓝绿工作台风格。
- 主色用于标题、关键数字和流程节点，正文使用深灰而非纯黑。
- AI、真实联网、平台本地三种来源必须保持稳定、可区分的状态色。
- 不使用大面积渐变、发光球或装饰性背景抢占信息注意力。

### 动画建议

- 流程图使用按阶段淡入，不使用复杂路径动画。
- 实机截图使用局部放大或遮罩高亮，不让整张截图反复移动。
- Git 分支页可按 Branch → Commit → Snapshot → Merge 顺序出现。
- 10 分钟答辩的整套动画数量控制在 15 次以内。

## 十二、术语表

| 术语 | 在本项目中的含义 |
| --- | --- |
| JD | Job Description，岗位职责与要求文本 |
| Main | 由当前目标岗位驱动的活动学习主线 |
| Side | 兴趣、补充能力或临时目标形成的学习支线 |
| Commit | 一次有时间、来源、证据和变化说明的学习动作 |
| Snapshot | 某次 Commit 后的完整能力状态 |
| Delta | 两个能力状态之间的新增、提升或下降差异 |
| Merge | 将支线中经过确认的能力成果并入主线 |
| Rollback | 在保留历史的前提下，将分支指针恢复到旧状态 |
| Evidence | 支撑评价或技能变化的答案、代码、项目和任务记录 |
| Impact | 某次评价对技能、计划和岗位匹配产生的影响 |
| Resource Ledger | 统一保存智能体生成内容与状态的资源台账 |
| Transparent Fallback | 将联网失败与 AI 补充明确显示为不同业务状态 |
