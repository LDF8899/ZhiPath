# ZhiPath 泛专业学习领域架构

## 产品定位

ZhiPath 的核心对象从“编程岗位技能”调整为“用户在某个专业领域中，为一个明确目标持续积累可验证能力”。职业发展仍是目标类型之一，但不再决定全部数据模型和交互。

## 核心模型

- `domainId`：学习所属领域，例如 `software-engineering`、`english`
- `goalType`：目标语义，支持 `career`、`course`、`exam`、`certificate`、`project`、`interest`
- `goalTitle`：用户可读目标，例如“大学英语六级 CET-6”
- `targetJobId`：仅在 `goalType = career` 时使用，继续兼容岗位匹配
- `planType`：只表示排期优先级，`main` 为核心目标，`side` 为并行目标，不再表示专业类别
- `passScore`：领域默认及格线，可随计划固化到 `pathData`，供速测、考试和进度练习统一使用
- `radarDimensions`：领域能力雷达契约，每个维度声明稳定 `id`、名称、关联能力项和权重

领域注册表位于 `backend-ts/src/domains/`。每个领域包声明可用目标类型、术语、评价方式、学习证据与起步路线。计划生成后仍复用现有任务调度、资源生成、学习分支和进度体系。

## 领域化评估与成长画像

`LearningAssessmentContextService` 根据用户当前核心计划解析统一评估上下文，包括领域、目标、当前能力、及格线、评价方式、证据类型、术语和雷达维度。速测、正式考试和学习进度练习都消费这份上下文，不再各自推断软件技能或固定使用 70 分及格线。

评估结果通过统一流水线沉淀为：

- 带领域前缀的评分规则，例如 `english_quick_test_v1`
- 领域及格线、维度、权重和评价方式
- 答题、作文版本、听力记录、步骤过程、案例论证或项目产物等领域证据
- 评价结果、能力变化、雷达变化、成长快照和下一步行动

成长档案继续复用原有快照和分支能力，但用户界面统一使用“学习轨迹”“学习证据”“成长快照”等学习语义。生成新快照时，系统优先使用当前领域的雷达契约；没有领域计划时才回退到旧的软件工程雷达。

首批领域默认及格线分别为：英语 60、数学 70、法律 60、软件工程 70。英语雷达包括词汇与语境、听力理解、阅读理解、写作与翻译、模拟与复盘；其他领域按各自注册表提供对应维度。

## 首批领域

### 软件工程

- 兼容原有岗位驱动路线
- 新增“全栈项目实战”项目型路线
- 证据包括代码提交、项目产物和技术说明

### 英语

- 首条路线为“大学英语六级 CET-6”
- 阶段依次为诊断与词汇、听力与阅读、写作与翻译、模拟与复盘
- 证据包括练习正确率、作文版本、听力记录和模拟卷成绩

### 数学

- 首条路线为“考研数学”
- 阶段依次为基础诊断、高数主干、线代与概率、真题与复盘
- 使用分步解题、章节测验、限时真题和错因诊断评价学习结果

### 法律

- 首条路线为“国家统一法律职业资格考试”
- 覆盖体系诊断、实体与程序法、案例论证、模拟与复盘
- 证据包括法条引用、案例论证、客观题正确率和主观题版本

## API

- `GET /api/user/learning-domains`
- `GET /api/user/learning-domains/:domainId`
- `POST /api/user/learning-paths`

领域路线创建请求示例：

```json
{
  "planType": "main",
  "domainId": "english",
  "goalType": "exam",
  "goalTitle": "大学英语六级 CET-6",
  "starterPathId": "cet-6",
  "dailyHours": 2
}
```

## 新增领域步骤

1. 在领域注册表中声明领域元数据与起步路线。
2. 为每个能力项提供稳定 `id`、名称、预估时长和优先级。
3. 声明 `passScore`、`radarDimensions`、评价方式与学习证据，避免所有领域复用编程题评价。
4. 确保雷达维度引用的能力 `id` 能在起步路线中物化为能力名称。
5. 为领域契约、路线阶段顺序、评估上下文和非法组合增加测试。
6. 在内容 Agent 中按 `domainId` 路由讲义、练习与评价提示词。

## 已接入的产品流程

- 首页以考试、课程、证书、项目、兴趣与职业等多目标学习为统一定位。
- Onboarding 收集背景、领域、起步路线、目标名称、每日时长和当前能力。
- 创建页区分专业路线、职业发展和自由探索，并将查询参数预填为领域计划。
- 资源 Agent 按领域术语、评价方式与证据类型生成讲义和练习，非软件领域不默认生成代码案例。
- AI 学习导师先识别领域、目标和基础，仅在明确求职意图时进入岗位推荐。
- 登录后导航以学习成长为主，职业发展保留为独立分支。
- Dashboard 根据 `goalType` 切换成长闭环：通用目标采用“学习画像 → 学习目标 → 学习计划 → 学习资源 → 学习行动 → 能力测评 → 成长画像”；职业目标继续兼容岗位差距、匹配变化和简历建议链路。
- 速测、考试和进度练习按领域及格线、评分规则和证据类型执行，并将结果写入统一成长档案。
- 成长画像按当前领域展示能力雷达；职业匹配信息仅作为职业目标的附加解释，不再定义通用学习结果。

## 后续泛化范围

- 跨领域画像：在领域雷达之外增加可比较的通用学习能力主干，但不稀释专业评价标准。
- 主观评价：为作文、证明过程、案例论证和项目作品接入可版本化的人工或 AI 评分规则。
- 领域包：将注册表拆成可独立发布、版本化和按需装载的领域模块。
