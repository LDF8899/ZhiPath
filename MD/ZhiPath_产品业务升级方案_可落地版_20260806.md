# ZhiPath 产品业务升级方案（可落地版）

> 角色视角：懂技术和市场的产品经理  
> 日期：2026-08-06  
> 目标：基于当前项目能力，给出下一阶段可排期、可验收、可演示、可转化的升级方案。  
> 原则：不画饼，不追求功能堆叠，优先打透“岗位导向成长闭环”。

---

## 1. 一句话结论

ZhiPath 下一步不应该继续横向扩功能，而应该把现有能力收敛成一条强主线：

```text
选定目标岗位
-> 看懂能力差距
-> 生成本周学习任务
-> 完成学习/测评/项目证据
-> 更新技能画像和岗位匹配度
-> 生成岗位版简历建议
```

产品升级的核心目标不是“让系统看起来更智能”，而是让用户在 7 天内明确感受到：

1. 我知道自己为什么不够格。
2. 我知道今天该做什么。
3. 我做完之后匹配度和简历表达确实变好了。

这条闭环打通后，ZhiPath 才能和普通学习平台、招聘平台、AI 聊天工具拉开差异。

## 2. 当前项目判断

### 2.1 已具备的基础

从现有仓库和页面结构看，ZhiPath 已经具备较完整的业务骨架：

| 模块 | 当前价值 | 下一步重点 |
| --- | --- | --- |
| Onboarding | 收集用户基础画像 | 进一步绑定目标岗位和时间预算 |
| 学习路径 | 支持岗位主线、自选计划、阶段任务 | 从“计划列表”升级为“今日推进器” |
| 岗位模块 | 支持本地/混合/联网搜索、匹配分析、岗位详情 | 强化岗位可信度分层和差距解释 |
| 测评模块 | 支持考试、速测、错题 | 让测评结果真正反哺画像和任务 |
| 进度模块 | 已有 Git 式学习记录概念 | 强化 commit/delta/impact 的可视化 |
| 简历模块 | 支持简历生成、岗位版简历 | 把学习证据翻译成岗位表达 |
| 智能体办公室 | 有差异化视觉和任务队列 | 从展示型升级为产出型工作台 |
| 管理端 | 用户、岗位、企业、考试、资讯等管理较全 | 服务学校/就业办的数据看板 |
| 视频生成工具 | 可生成项目演示视频 | 作为内容生产能力，不作为主业务线 |

### 2.2 主要问题

当前不是“缺一个大功能”的问题，而是业务焦点还不够尖。

| 问题 | 表现 | 影响 |
| --- | --- | --- |
| 主路径不够强 | 用户能去很多页面，但不一定知道今天该做什么 | 新用户留存和任务完成率低 |
| 个性化不够可感知 | 有画像、岗位、计划，但用户不一定理解两者如何联动 | AI 价值感弱 |
| 匹配度解释不够产品化 | 分数存在，但需要更清楚说明为什么、怎么提升 | 信任不足 |
| 学习证据没有充分资产化 | 学习、测评、项目、简历之间还需要更强连接 | 结果感不足 |
| 智能体产出验收不够明确 | Agent 有任务，但产出如何进入学习/简历/知识库要更顺 | 容易被看成装饰功能 |
| 市场切入点需要收窄 | C 端、B 端、招聘端都能讲，但不能同时主攻 | 销售和演示难聚焦 |

## 3. 市场定位升级

### 3.1 不建议的定位

不建议把 ZhiPath 定位成以下几类：

| 定位 | 为什么不建议 |
| --- | --- |
| AI 学习平台 | 竞争太泛，容易被课程平台和通用 AI 工具覆盖 |
| AI 招聘平台 | 会正面对上 Boss、猎聘、智联等平台，岗位供给不是优势 |
| AI 简历工具 | 价值太窄，容易被低价工具替代 |
| 智能体平台 | 对学生和学校用户太抽象，业务价值不直观 |

### 3.2 建议定位

建议定位为：

> 面向学生的岗位能力成长平台。

更完整的表达：

> ZhiPath 帮学生从目标岗位出发，看清技能差距，生成个性化学习任务，并通过测评、项目和简历证据持续提升求职准备度。

### 3.3 差异化关键词

建议对外重点使用这四个词：

1. 岗位导向
2. 能力差距
3. 学习证据
4. 求职准备度

不要过度强调“大模型”“多智能体”“知识图谱”等技术词。技术应该作为支撑，不作为第一层卖点。

## 4. 目标用户与优先级

### 4.1 第一优先级：在校学生

典型问题：

- 不知道目标岗位到底要求什么。
- 不知道自己和岗位差多少。
- 学习计划太泛，不能直接服务就业。
- 简历和项目缺乏岗位表达。

ZhiPath 的价值：

- 把岗位要求拆成技能差距。
- 把差距转成每日任务。
- 把学习过程转成可写进简历的证据。

### 4.2 第二优先级：高校就业办/学院

典型问题：

- 只知道学生是否就业，不知道就业准备度。
- 课程和岗位要求之间缺少可视化映射。
- 缺少学生群体技能短板数据。

ZhiPath 的价值：

- 展示学生目标岗位分布。
- 展示群体技能缺口。
- 展示学习任务完成率和测评达标率。
- 为就业指导、课程优化、实训安排提供数据。

### 4.3 第三优先级：转岗/补技能用户

这类用户有价值，但建议作为第二阶段拓展。

原因：

- 需求强，但付费转化和获客成本不确定。
- 路径比在校学生更复杂，需要更强行业经验和岗位数据。
- 当前项目更适合先在校园就业场景形成闭环。

### 4.4 暂不主攻：企业招聘方

企业端可以保留为远期方向，但短期不建议主攻。

原因：

- 企业最关心真实候选人供给和招聘效率。
- 当前 ZhiPath 的优势在“培养”和“准备”，不是岗位供给。
- 过早做企业端会分散主线。

## 5. 核心升级方向：从功能集合到岗位成长闭环

### 5.1 升级前后对比

| 维度 | 当前状态 | 升级后状态 |
| --- | --- | --- |
| 首页 | 展示学习、任务、岗位、资讯等多个模块 | 明确告诉用户今天最该做什么 |
| 岗位详情 | 展示岗位信息和匹配分析 | 成为学习目标入口和差距解释中心 |
| 学习计划 | 展示阶段和任务 | 根据岗位差距动态生成本周任务 |
| 测评 | 独立考试/速测 | 作为技能掌握证据，影响画像和匹配度 |
| 简历 | 生成简历内容 | 把学习证据转成岗位版表达 |
| 智能体办公室 | 任务队列和角色展示 | 异步产出讲义、练习、项目、简历建议 |

### 5.2 黄金路径

建议把 MVP 黄金路径定义为：

```text
新用户注册
-> 完成画像
-> 选择目标岗位
-> 查看岗位差距卡
-> 生成 7 天学习任务
-> 完成 1 个学习任务和 1 次速测
-> 匹配度发生变化
-> 生成岗位版简历建议
```

这条路径的验收标准：

| 节点 | 验收标准 |
| --- | --- |
| 选择岗位 | 用户能从本地岗位或联网参考岗位中选定目标 |
| 差距卡 | 展示 Top 3 缺口、当前分数、建议动作 |
| 7 天任务 | 至少生成 5 个可完成任务，并区分学习/练习/测评/项目 |
| 完成任务 | 任务状态能更新，并记录学习 commit |
| 画像变化 | 对应技能掌握度发生变化 |
| 匹配度变化 | 目标岗位匹配度重新计算，并展示原因 |
| 简历建议 | 生成至少 3 条岗位化表达建议 |

## 6. 个性化升级方案

### 6.1 个性化不是推荐课程

ZhiPath 的个性化应该基于以下变量：

```text
用户画像
+ 目标岗位
+ 技能差距
+ 每日可用时间
+ 学习阶段
+ 测评结果
+ 项目证据
+ 简历短板
+ 岗位来源可信度
```

最终生成的不是“课程推荐”，而是：

```text
今天该做什么
为什么要做
做完能提升什么
如何证明你会了
能不能写进简历
```

### 6.2 岗位差距卡

这是下一阶段最值得优先做的产品组件。

#### 页面位置

- 首页顶部
- 岗位详情右侧
- 学习计划页侧栏

#### 展示内容

| 字段 | 示例 |
| --- | --- |
| 目标岗位 | 前端开发实习生 |
| 当前匹配度 | 58% |
| 投递建议 | 暂不建议投递，先补齐 React 状态管理和项目部署 |
| 关键缺口 Top 3 | React Hooks、接口联调、项目上线 |
| 最快提升任务 | 完成 Hooks 练习 + Todo 项目改造 |
| 预计影响 | 完成后预计匹配度 +6% |

#### 验收标准

1. 没有目标岗位时，提示选择目标岗位。
2. 有目标岗位时，展示匹配度和缺口。
3. 缺口能一键加入学习计划。
4. 每个缺口有推荐动作。
5. 推荐动作能跳转到学习/测评/项目/简历。

### 6.3 今日个性化任务

首页不应该只是信息展示，而应该是行动入口。

#### 任务生成规则

优先级建议：

1. 目标岗位必备技能缺口。
2. 上次测评暴露的薄弱点。
3. 学习计划中已开始但未完成的任务。
4. 能生成简历证据的项目任务。
5. 低成本复习任务。

#### 任务卡字段

| 字段 | 说明 |
| --- | --- |
| 任务标题 | 完成 React Hooks 练习 |
| 任务类型 | 学习/练习/测评/项目/简历 |
| 预计时间 | 25 分钟 |
| 推荐原因 | 目标岗位要求 React 状态管理，你当前掌握度 45% |
| 预计影响 | 完成后匹配度预计 +3% |
| 证据沉淀 | 完成后生成学习 commit 和技能 delta |

#### 验收标准

1. 每天最多展示 3 个主任务。
2. 每个任务必须有推荐原因。
3. 任务完成后必须产生记录。
4. 任务完成后至少影响一个指标：技能、进度、测评、简历或匹配度。

### 6.4 学习证据链

这是 ZhiPath 的核心特色之一。

#### 技能详情应展示

| 内容 | 示例 |
| --- | --- |
| 当前掌握度 | React 70% |
| 来源 | 来自前端开发岗位必备技能 |
| 学习证据 | 已完成 Hooks 讲义 |
| 测评证据 | 组件状态题 8/10 |
| 项目证据 | Todo 项目中使用 useEffect |
| 简历表达 | 使用 React 构建任务管理模块 |
| 岗位影响 | 目标岗位匹配度 +8% |

#### 验收标准

1. 一个技能能追溯到至少一种证据。
2. 测评结果能进入证据链。
3. 项目经历能绑定技能。
4. 简历建议能引用证据。

## 7. 特色化升级方案

### 7.1 特色一：岗位驱动学习

核心表达：

> 不是先学课程再找岗位，而是先看岗位差距，再安排学习。

落地方式：

- 岗位详情页增加“作为学习目标”主按钮。
- 缺失技能支持一键加入主线或支线计划。
- 计划页展示每个任务来自哪个岗位要求。
- 首页展示目标岗位差距。

### 7.2 特色二：Git 式成长记录

核心表达：

> 每一次学习都像一次 commit，能看到能力 delta 和岗位 impact。

落地方式：

```text
commit: 完成 React Hooks 练习
delta: React +6%，状态管理 +4%
impact: 前端实习岗位匹配度 58% -> 63%
evidence: 练习结果、项目片段、简历表达
```

近期不需要做复杂图谱，先做可用列表和对比即可。

#### 第一阶段展示

- 时间线列表
- 每条记录展示学习动作、技能变化、匹配度变化
- 支持按计划、技能、岗位过滤

#### 第二阶段展示

- 分支视图
- 前后快照对比
- 回滚和合并说明

### 7.3 特色三：可解释匹配度

核心表达：

> 不只告诉你 58%，还告诉你为什么是 58%，以及怎么变成 70%。

匹配度建议拆成：

| 维度 | 建议权重 | 说明 |
| --- | --- | --- |
| 必备技能覆盖 | 35% | 是否满足岗位基本门槛 |
| 加分技能覆盖 | 15% | 是否具备竞争优势 |
| 测评证据 | 20% | 是否通过练习/考试证明掌握 |
| 项目证据 | 20% | 是否有可写进简历的实践 |
| 学习活跃度 | 10% | 最近是否持续推进 |

注意：权重可以先写死，后续再做后台配置，不要一开始做复杂规则引擎。

### 7.4 特色四：学生成长资产化

核心表达：

> ZhiPath 不只记录学习过程，而是把学习过程变成求职资产。

资产包括：

- 能力画像
- 学习 commit
- 测评结果
- 项目证据
- 岗位版简历
- 投递建议
- 阶段成长报告
- 项目演示视频

近期优先做前三个资产打通，不要一次做完整报告系统。

## 8. 具体功能升级清单

### 8.1 P0：两周内必须打透

#### P0-1 岗位差距卡

目标：

让用户看到自己和目标岗位的差距，并知道下一步做什么。

页面：

- 首页
- 岗位详情页

功能：

- 展示当前匹配度。
- 展示 Top 3 缺失技能。
- 展示推荐任务。
- 展示预计提升。
- 支持加入学习计划。

技术实现：

- 后端复用岗位匹配和技能画像数据。
- 新增或扩展接口：`GET /api/user/jobs/:id/gap-card`
- 前端新增 `JobGapCard` 组件。

验收：

- 任意本地岗位可生成差距卡。
- 无技能画像时能给出基础建议。
- 缺失技能能跳转到计划创建或加入支线。

#### P0-2 首页今日任务收敛

目标：

让首页变成用户每日行动入口。

功能：

- 首页顶部显示 1 个主任务和最多 2 个辅助任务。
- 每个任务展示推荐原因。
- 每个任务展示预计影响。
- 完成任务后刷新进度和匹配度。

技术实现：

- 后端新增或扩展：`GET /api/user/today-actions`
- 任务来源先用规则排序，不需要大模型。
- 规则优先级：岗位缺口 > 未完成任务 > 测评薄弱点 > 简历短板。

验收：

- 新用户有兜底任务：选择目标岗位或创建计划。
- 老用户有学习/测评/项目任务。
- 任务完成后有状态变化。

#### P0-3 学习 commit 与匹配度变化联动

目标：

用户完成任务后能看到“我变强了多少”。

功能：

- 完成学习任务生成 commit。
- commit 记录技能 delta。
- 如果绑定目标岗位，重新计算匹配度。
- 首页弹出匹配度变化提示。

技术实现：

- 复用现有 Git 学习系统。
- 补齐任务完成 -> skill snapshot -> match recalculation 的调用链。

验收：

- 完成一个任务后，进度页出现一条记录。
- 目标岗位匹配度能发生变化或说明无显著变化。
- 变化原因可读。

### 8.2 P1：四周内完成

#### P1-1 技能证据链

目标：

让技能掌握度有依据，不只是数字。

功能：

- 技能详情展示学习、测评、项目、简历证据。
- 简历生成时优先引用有证据的技能。

技术实现：

- 新增 `SkillEvidence` 视图模型即可，先不一定新建表。
- 从学习 commit、evaluation result、project、resume content 聚合。

验收：

- 至少 5 个核心技能能展示证据链。
- 简历建议能引用项目或测评结果。

#### P1-2 岗位版简历建议升级

目标：

把学习成果转成岗位语言。

功能：

- 对目标岗位生成 3-5 条简历表达建议。
- 标明每条建议引用了哪些技能和证据。
- 对证据不足的技能提示“建议补项目/测评”。

技术实现：

- 后端简历服务增加 evidence-aware prompt。
- 先生成建议文本，不急于做复杂模板编辑器。

验收：

- 岗位版简历能体现岗位关键词。
- 建议能解释来源。
- 证据不足时不给过度包装。

#### P1-3 智能体产出闭环

目标：

Agent 产物能进入业务主线。

功能：

- 讲义 Agent 产物进入知识详情。
- 练习 Agent 产物进入测评/练习。
- 项目 Agent 产物进入项目任务。
- 简历 Agent 产物进入简历建议。

技术实现：

- 每个 Agent 任务必须有 `outputType` 和 `targetEntity`。
- 前端任务中心按产物类型给出操作按钮。

验收：

- Agent 产物不是只显示在任务详情里。
- 至少 3 类产物可以一键进入对应业务页面。

### 8.3 P2：六到八周完成

#### P2-1 学院/就业办数据看板

目标：

支持 B 端演示和试点落地。

功能：

- 学生目标岗位分布。
- 技能缺口 Top 10。
- 学习任务完成率。
- 测评达标率。
- 求职准备度分层。

技术实现：

- 管理端新增就业准备度看板。
- 后端先做聚合接口，不引入复杂 BI 系统。

验收：

- 能按班级/专业/年级过滤。
- 能导出基础 CSV。
- 能支撑一次学校场景演示。

#### P2-2 阶段成长报告

目标：

让学生和老师看到阶段成果。

功能：

- 近 7/30 天学习记录。
- 技能变化。
- 测评表现。
- 岗位匹配变化。
- 下一步建议。

技术实现：

- 先做页面报告，不急于 PDF。
- 后续可用视频工具生成演示版。

验收：

- 一个学生可生成完整阶段报告。
- 报告可用于演示或就业指导。

## 9. 技术落地建议

### 9.1 不建议立刻做的技术

| 技术/功能 | 暂缓原因 |
| --- | --- |
| 复杂推荐算法 | 当前数据量不足，规则引擎更快更可控 |
| 完整知识图谱可视化重构 | 成本高，对黄金路径帮助有限 |
| 企业招聘端 | 会拉长业务链条 |
| 全量数据中台 | 当前阶段用聚合接口足够 |
| 大规模多智能体编排 | 先把产出闭环跑通 |
| 复杂简历编辑器 | 先做岗位建议和证据引用 |

### 9.2 建议采用的实现方式

#### 今日任务规则

先用规则排序：

```text
score =
岗位必备技能缺口权重
+ 测评薄弱权重
+ 未完成任务权重
+ 项目证据缺口权重
+ 用户每日时间适配权重
```

不用一开始就上复杂 AI 推荐。

#### 匹配度解释

先做结构化解释：

```json
{
  "score": 58,
  "reason": "必备技能覆盖不足，React Hooks 和接口联调掌握度较低",
  "topGaps": ["React Hooks", "接口联调", "项目部署"],
  "nextActions": [
    {
      "title": "完成 React Hooks 练习",
      "estimatedImpact": 3
    }
  ]
}
```

LLM 可以用于润色解释，但核心计算要规则化。

#### 证据链聚合

第一阶段不必重建复杂数据模型，可以聚合现有数据：

| 证据类型 | 来源 |
| --- | --- |
| 学习证据 | learning commit / learning task |
| 测评证据 | evaluation attempt / result |
| 项目证据 | projects / resume content |
| 简历证据 | resume advice / generated resume |
| 岗位影响 | match history / skill snapshot |

## 11. 路线图

### 第 1-2 周：打通黄金路径

交付：

1. 岗位差距卡。
2. 首页今日任务收敛。
3. 任务完成后生成 commit。
4. 匹配度变化提示。
5. 岗位详情“作为学习目标/加入学习计划”体验优化。

验收演示：

```text
选择一个前端岗位

-> 生成今日任务
-> 完成 React 练习
```

交付：

1. 技能证据链。

3. Agent 产物进入学习/练习/简历页面。
4. 进度页展示 commit impact。

验收演示：

```text
打开 React 技能
-> 看到学习、测评、项目证据
-> 生成岗位版简历建议
-> 每条建议能追溯到学习证据
```

### 第 5-8 周：服务学校场景

交付：

1. 就业准备度看板。
2. 技能缺口统计。
3. 学生阶段成长报告。
4. 班级/专业维度筛选。

验收演示：

```text
管理员进入后台
```

## 13. 演示话术

建议演示时不要从技术架构开始，而从学生问题开始：

```text
很多学生不是不努力，而是不知道自己离目标岗位差什么。
ZhiPath 从一个目标岗位开始，把岗位要求拆成能力差距，
再把差距变成今天能完成的学习、测评和项目任务。
```

1. 选择目标岗位。
2. 查看差距卡。

4. 完成任务。
5. 匹配度变化。
6. 简历建议变化。
7. 管理端查看群体技能缺口。

这套演示比展示一堆页面更有说服力。

## 15. 下一步可直接拆的需求卡

### 需求卡 1：岗位差距卡

用户故事：

> 作为学生，我希望看到自己和目标岗位的关键差距，这样我知道先补什么。

验收：

- 展示匹配度。
- 展示 Top 3 缺口。
- 展示推荐动作。
- 支持加入学习计划。

### 需求卡 2：今日任务推荐

用户故事：

> 作为学生，我希望每天看到 1-3 个最该完成的任务，而不是自己在功能菜单里找。

验收：

- 有目标岗位时，任务优先来自岗位缺口。
- 无目标岗位时，引导选择岗位。
- 每个任务有原因和预计影响。

### 需求卡 3：任务完成生成 commit

用户故事：

> 作为学生，我希望完成学习任务后看到能力变化，而不是只看到“已完成”。

验收：

- 完成任务生成学习记录。
- 记录包含技能变化。
- 如果有目标岗位，触发匹配度重算。

### 需求卡 4：岗位版简历建议

用户故事：

> 作为准备投递的学生，我希望系统把我的学习成果改写成适合目标岗位的简历表达。

验收：

- 生成 3-5 条建议。
- 每条建议关联技能或项目证据。
- 证据不足时提示补项目或测评。

### 需求卡 5：学校就业准备度看板

用户故事：

> 作为就业指导老师，我希望看到学生群体的岗位目标和技能缺口，以便做就业辅导。

验收：

- 展示目标岗位分布。
- 展示技能缺口 Top 10。
- 展示任务完成率和测评达标率。
- 支持按专业/班级/年级筛选。

## 16. 最终建议

ZhiPath 的升级重点不是再证明“我们有 AI、Agent、图谱、视频”，而是证明：

```text
学生选择一个岗位后，
系统能持续告诉他差什么、学什么、怎么证明、怎么写进简历。
```

下一阶段最务实的打法：

1. 用两周打通 7 天岗位成长闭环。
2. 用四周强化学习证据链和岗位版简历。
3. 用八周做出学校就业准备度看板。

这条路线既能服务学生，也能服务学校试点；既有技术差异化，也有市场落点；既能演示，也能验收。
