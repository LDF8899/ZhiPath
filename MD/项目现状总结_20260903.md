## 0.3 2026-09-03 深夜二批：视频无声问题（TTS 修复）

**现象**：成片有 aac 音轨但 volumedetect 实测 -91dB 纯静音，输出目录无任何音频文件。

**根因**：TTS 默认走 MiMo（小米）API，但 `.env` 没配 `MIMO_API_KEY`（启动日志 `MiMo API key loaded: EMPTY`），调用 401 后**静默降级为"时长估算"**——不生成音频、任务仍报"配音合成完成"，无声视频伪装成正常完成。

**修复（按用户决定弃用 MiMo，直接 Edge）**：
1. `tts.service.ts` 默认 `TTS_PROVIDER` 从 mimo 改为 **edge**（微软 Edge 朗读，免费无需 key；`python -m edge_tts`，已 pip 安装）；换回 MiMo 只需配 `MIMO_API_KEY` + `TTS_PROVIDER=mimo`
2. 顺手修 TTS 输出目录同款 Windows 路径 bug：`/tmp/zhipath/tts` → `backend-ts/output/tts`
3. **诚实性修复**：video-agent 在 TTS 全部降级时进度消息明说"配音合成失败，将生成无声视频"，result 增加 `tts_status: silent|voiced`；action-executor 任务快照带上该字段；前端视频卡对无声版显示"无声版（配音合成失败，可重新生成）"

**验证**：Edge TTS（晓晓语音）本机合成 -20dB 正常；重新生成《HTTP Request Lifecycle》视频：1080p / 2:21 / **mean -22.6dB / max -3.7dB 真实人声**，画面质量同前。


## 1. 项目定位

ZhiPath / SkillStudio 是一个面向 AI-native 软件开发能力成长的学习平台。核心目标不是单纯做课程播放或题库，而是把学习画像、学习路径、智能体生成、练习测评、资源沉淀和成长报告串成闭环。

当前主工程分为三块：

| 模块 | 路径 | 状态 |
|---|---|---|
| 后端 | `backend-ts` | NestJS + TypeORM + MySQL，核心业务接口可用，仍需补强稳定性与迁移脚本体系 |
| 新前端 | `codenovafrontend` | React + Vite，新工作台主线，已接入登录、画像、路径、学习、聊天、资源、报告、Agent、严格出题 |
| 老前端 | `frontend` | 参考实现来源，部分旧流程仍需迁移到新前端 |

## 2. 当前产品主链路

当前已形成的主链路：

```text
登录 / 注册
-> Onboarding 学习画像
-> 学习路径生成
-> 今日工作台
-> 技能学习闭环：讲义 / 测验 / 实操 / 掌握度回写
-> AI 教练：会话机制 / action 卡片 / 资源关联
-> 资源库：按任务、会话、类型追踪生成资源
-> 成长报告：能力雷达、薄弱项、趋势
-> Agent 工作台：多智能体分类展示与任务台账
-> 严格出题器：智能体配置 / 学习程度匹配 / 手动配置 -> 生成 -> 审核 -> 入库
```

其中“严格出题器”已经从老前端恢复到新前端，避免聊天智能体直接给出随意题目。现在题目参数可以来自多种入口，但核心生成管线保持统一。

| 入口 | 说明 |
|---|---|

最终统一走：

```text
创建出题任务
-> 启动异步生成
-> 轮询快照
-> 审核题目
-> 保存草稿
-> 批准入题库
```
