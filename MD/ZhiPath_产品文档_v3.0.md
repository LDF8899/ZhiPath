# 智途 ZhiPath 产品文档

> 当前版本：v4.0
> 更新日期：2026-07-23
> 文档定位：用于产品评审、研发对齐和后续迭代规划。旧 v3.0 文档中的 Python 到 TypeScript 迁移内容已不再作为主线。

## 1. 产品定位

ZhiPath 是面向学生的 AI 学习与就业准备平台。产品核心不是“生成一份学习计划”，而是围绕目标岗位建立持续闭环：

```text
了解我是谁 -> 明确我想去哪 -> 拆解差距 -> 安排学习
-> 产生资源 -> 完成练习/测评 -> 更新画像 -> 重新匹配岗位
```

一句话价值：让学生知道自己离目标岗位还差什么，并把学习、测评、简历和投递串成可执行路径。

## 2. 目标用户

| 用户 | 主要诉求 | 产品价值 |
| --- | --- | --- |
| 在校学生 | 不知道学什么、岗位要求看不懂、简历和项目弱 | 获得岗位导向的学习路线、资源、测评和投递建议 |
| 转岗/补技能用户 | 想快速判断能力差距 | 通过技能画像、岗位匹配和专项学习补齐短板 |
| 平台管理员 | 维护岗位、考试、资讯、企业和用户 | 提供运营后台和内容治理入口 |
| 企业/就业服务方 | 找到更匹配的候选人 | 通过投递、简历和匹配评分提升初筛效率 |

## 3. 产品目标

短期目标：

- 让学生完成从画像到学习计划的首轮闭环。
- 让岗位搜索结果足够可信，既有本地岗位，也能补充联网结果。
- 让智能体办公室从“装饰性角色”变成可感知、可追踪的生产系统。
- 让每次学习、练习、考试、项目导入都能沉淀到画像和匹配度。

核心指标：

| 指标 | 含义 |
| --- | --- |
| Onboarding 完成率 | 用户是否能顺利建立初始画像和目标 |
| 学习计划创建率 | 是否形成可执行路径 |
| 任务完成率 | 智能体生成的讲义、练习、代码等资源是否被完成 |
| 测评完成率 | 用户是否进入练习和评估闭环 |
| 岗位详情打开率 | 搜索结果是否有足够吸引力和可信度 |
| 技能导入率 | 用户是否愿意把岗位差距导入学习计划 |
| 投递转化率 | 学习和简历是否最终指向就业动作 |

## 5. 核心体验闭环

### 5.1 新用户引导

1. 用户注册/登录。
2. 学生进入 onboarding，填写专业、年级、技能、目标方向等信息。
3. 系统生成初始画像，并推荐目标岗位或学习方向。
4. 用户确认目标后进入计划生成。
5. 首页展示目标、学习任务、能力雷达和下一步动作。

产品要求：

- 不让用户先面对复杂功能菜单，而是先建立“目标岗位”和“能力差距”。
- Onboarding 需要支持随时补充画像，不能变成一次性表单。

### 5.2 学习路径与知识资源

学习路径由阶段和技能组成，每个技能可以进入知识详情页。知识详情页承载讲义、练习、代码案例、相关阅读等资源。

资源来源包括：

- 系统内置知识库。
- 智能体办公室异步生成。
- AI 助教对话触发生成。
- 学习过程、测评结果和岗位技能导入触发补充。

产品要求：

- 用户要能区分“计划中的技能”“已完成技能”“岗位补齐技能”。
- 资源生成不能只存在当前页面内存，必须沉淀到资源台账和知识库。

### 5.3 Git 式学习记录

学习行为被记录为类似 Git 的结构：

| 概念 | 产品含义 |
| --- | --- |
| Branch | 一条学习计划或目标方向 |
| Commit | 一次学习动作，如阅读、练习、代码、考试 |
| Snapshot | 某一时刻的能力快照 |
| Delta | 两次快照之间的能力变化 |
| Merge/Rollback | 学习路径调整、能力记录修正 |

该机制用于支撑进度页、技能雷达、匹配度变化和后续复盘。

### 5.4 测评闭环

测评不只是出题和打分，而是进入画像更新：

```text
学习动作 -> 快速测试/考试/AI 评估 -> evaluation attempt
-> result -> impact -> 技能雷达/匹配度/学习计划调整
```

产品要求：

- 快速测试适合轻量诊断。
- 正式考试适合阶段验收。
- 错题页负责复盘和针对性补练。
- 岗位详情中的缺失技能可以导入学习计划。

## 6. 岗位模块

### 6.1 搜索模式

岗位列表接口：

```text
GET /api/user/jobs
```

主要参数：

| 参数 | 说明 |
| --- | --- |
| `keyword` | 搜索关键词 |
| `company` | 公司过滤 |
| `location` | 城市/地点过滤 |
| `level` | 岗位等级 |
| `searchMode` | `local`、`hybrid`、`online` |
| `includeOnline` | 是否主动包含联网结果 |

三种策略：

| 模式 | 策略 | 使用场景 |
| --- | --- | --- |
| `local` | 只查 MySQL 岗位库 | 稳定、可运营、可投递的岗位 |
| `hybrid` | 本地多字段检索 + 联网补充 + 去重排序 | 默认搜索体验 |
| `online` | 只返回联网候选岗位 | 探索外部机会和市场参考 |

### 6.2 本地搜索

本地搜索覆盖字段：

- 岗位标题
- 公司
- 城市/地点
- 薪资
- JD 正文
- 必备技能
- 加分技能

本地结果会结合用户画像，通过匹配算法计算分数并排序。

### 6.3 联网搜索

联网岗位搜索策略：

1. 用关键词拼接招聘意图，如 `React 招聘`。
2. 调用 Search Stack，多引擎搜索外部网页。
3. 用 LLM 从搜索结果标题、链接和摘要中提取结构化岗位卡片。
4. 如果外部搜索不可用，或有效岗位不足，则用 LLM 按市场常识生成候选岗位作为兜底。
5. 根据用户技能计算一个轻量匹配度。
6. 与本地结果合并、去重、排序。

联网结果的边界：

- 联网结果更适合做市场探索，不等同于平台可直接投递岗位。
- 有真实 URL 的结果标记为 `origin=web`。
- AI 兜底生成的结果标记为 `origin=ai_generated`，页面应降低“确定性”表达。
- 联网候选需要展示来源、摘要和更新时间，避免用户误认为是平台官方岗位。

缓存策略：

- 联网结果按 `关键词 + 用户技能集合` 生成缓存键。
- 后端内存缓存 15 分钟。
- 切换页面、返回列表或重复查询时应优先复用缓存，减少外部搜索和 LLM 调用。
- Search Stack 自身也可以具备服务级缓存。

### 6.4 岗位详情与地图

岗位详情页展示：

- 岗位基本信息：标题、公司、城市、薪资、等级。
- 技能要求：必备技能和加分技能。
- JD 正文和摘要。
- 匹配分析：匹配分、已匹配技能、缺失技能、是否达到投递阈值。
- 企业介绍：由企业信息、岗位信息和 LLM 生成的克制型简介。
- 地图：使用高德地理编码和静态图/JSAPI 展示公司或岗位位置。
- 行动：申请岗位、导入缺失技能到学习计划。

产品要求：

- 本地岗位详情是强确定性页面。
- 联网岗位详情需要清楚展示来源，并对不完整字段做降级展示。
- 地图不应只服务本地岗位，联网岗位只要有公司和城市，也应尝试补全位置。

## 7. 智能体办公室

### 7.1 产品定位

智能体办公室是 AI 能力的可视化任务中心。它解决两个问题：

- 让用户知道 AI 正在做什么，而不是等待一个黑盒结果。
- 把生成的讲义、练习、代码、阅读、测评、简历等资源沉淀为可复用资产。

### 7.2 Agent 类型

| Agent | 职责 |
| --- | --- |
| 讲义专家 | 生成结构化讲义 |
| 阅读向导 | 推荐拓展阅读 |
| 代码大师 | 生成代码案例 |
| 路径规划 | 生成学习路径 |
| 评估专家 | 评估学习效果 |
| 出题专家 | 生成考试/练习题 |
| 差距分析师 | 分析岗位技能差距 |
| 简历顾问 | 生成或优化简历 |
| 画像分析师 | 更新用户画像 |
| 资讯编辑 | 生成资讯趋势分析 |

### 7.3 员工形象与状态

当前办公室形象要求：

- 员工不再使用随机宠物感形象，而是专业、统一、各具角色特征的办公员工。
- 不同 Agent 通过服装、配色、道具和工种细节区分。
- 办公室应更像生产空间：工位、屏幕、任务状态、资源面板、历史产出都要服务任务理解。

状态语义：

| 状态 | 产品表现 |
| --- | --- |
| 空闲 | 员工不占用工位，可在公共区域或待命区展示 |
| 待处理 | 员工进入对应工位，显示排队/准备中 |
| 运行中 | 员工在工位工作，展示进度和当前任务 |
| 成功 | 任务进入历史和资源台账，员工离开工位 |
| 失败 | 展示错误，资源标记失败，员工离开工位 |
| 取消 | 任务终止，释放工位 |

关键规则：

- 只有存在 `pending` 或 `running` 任务的 Agent 才应该在工位上。
- 任务完成后，如果该 Agent 没有其它运行中任务，必须释放工位。
- 页面刷新时要校正历史残留状态，避免“没任务但工位有人”。

## 8. AI 助教

AI 助教是跨页面的轻量入口：

- 在聊天页承担完整对话和任务触发。
- 在学习、岗位、资讯等页面承担上下文辅助。
- 能触发推荐岗位、生成学习计划、出题、展示进度、推荐资源等动作。

产品原则：

- 助教回答必须尽量落到可执行动作，而不是泛泛建议。
- 当动作会产生长耗时内容时，进入智能体办公室任务队列。
- 重要结果要持久化，不依赖当前对话窗口内存。

| 数据 | 存储 | 说明 |
| --- | --- | --- |
| 用户/学生/岗位/企业/投递 | MySQL | 结构化业务数据 |
| 学习路径/计划 | MySQL | 用户学习计划、阶段和任务 |
| 测评记录 | MySQL | attempt/result/impact |
| Git 学习记录 | MySQL | branch/commit/snapshot/delta |
| 用户画像 | MongoDB | 技能、目标、兴趣、项目、洞察 |
| 聊天历史 | MongoDB/Redis | 对话长期/短期上下文 |
| 资源台账 | MySQL | 智能体生成资源的任务结果 |
| 知识库内容 | MongoDB | 讲义、练习、代码、阅读材料 |
| 技能图谱 | Neo4j | 技能关系和路径依赖 |
| 缓存/队列 | Redis/BullMQ | 搜索缓存、任务队列、活跃状态 |

## 10. 当前版本重点变化

截至 2026-07-23，当前版本相对旧文档的关键变化：

- 前后端已统一为 React + NestJS 的 TypeScript 栈。
- 岗位搜索升级为本地、混合、联网三模式，并加入联网结果缓存。
- 岗位详情补充企业介绍和地图能力，联网岗位也应尽量补齐详情体验。
- 智能体办公室升级为专业员工形象，不再使用宠物感角色。
- 智能体工位状态和任务状态绑定，完成、失败、取消后释放工位。
- 资源生成沉淀到资源台账，避免切页丢失。
- Git 学习系统和 evaluation spine 支撑长期画像更新。

## 11. 产品风险

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 联网岗位真假混杂 | 用户可能误解为平台官方岗位 | 明确 `web`/`ai_generated` 来源，优先展示原链接和抓取时间 |
| AI 兜底岗位过于模糊 | 降低信任 | AI 兜底结果单独标识，并限制用于探索，不直接投递 |
| 画像更新链路不可见 | 用户不知道为什么匹配度变化 | 在进度页展示“本次测评影响了哪些技能” |
| 智能体办公室沦为装饰 | 用户无法理解任务价值 | 强化任务、进度、产物、历史，不只展示角色 |
| 资源质量不稳定 | 学习体验受影响 | 加入评分、收藏、重生成、人工审核和版本记录 |
| 管理端运营不足 | 岗位和题库质量难维持 | 增加内容审核流、来源管理、批量导入和质量统计 |

## 12. 后续优化建议

优先级 P0：

- 联网岗位详情补强：来源、抓取时间、外链、地图、字段置信度。
- 岗位搜索结果持久缓存：从内存缓存升级到 Redis，可跨进程和重启复用。
- 智能体工位一致性：前后端共同以任务状态为准，不允许纯视觉残留。
- 资源台账入口统一：聊天、学习页、办公室生成的资源都能在一个地方找回。

优先级 P1：

- 建立“岗位可信度”标签：平台岗位、企业岗位、联网岗位、AI 参考岗位。
- 增加学习计划变更说明：为什么新增/删除某个技能。
- 简历和岗位详情联动：针对某岗位生成定制简历建议。
- 测评结果解释：展示每道题对应的技能点和对雷达的影响。

优先级 P2：

- 管理后台增加内容质量看板。
- 引入用户反馈闭环：资源有用/无用、岗位准确/不准确。
- 增加企业侧轻量入口。
- 对前端大 chunk 做路由级代码拆分。

## 13. 验收口径

一个完整用户场景应能满足：

1. 新用户完成画像和目标选择。
2. 系统生成学习计划。
3. 用户在学习路径中打开技能详情并生成资源。
4. 智能体办公室显示任务执行，完成后员工离开工位。
5. 资源可以在切页后继续找回。
6. 用户完成测试后，进度和画像有可解释变化。
7. 用户搜索岗位，本地和联网结果不会因切页重复刷新。
8. 用户打开岗位详情，能看到技能要求、匹配分析、企业介绍和地图。
9. 用户将缺失技能导入学习计划。
10. 用户生成或优化简历并进入投递流程。

## 14. 研发对齐

当前技术实现：

- 前端：React 19 + Vite 8 + TypeScript + React Router + Zustand。
- 后端：NestJS 11 + TypeORM + MongoDB/Mongoose + Redis + BullMQ。
- AI：OpenAI-compatible SDK，支持 DeepSeek、MiMo、Ollama 等 provider。
- 搜索：Search Stack/SearXNG，岗位模块带 LLM 结构化提取和兜底生成。
- 地图：高德 Web JSAPI 与 Web Service。

开发原则：

- 新增页面必须接入真实业务状态，不做纯静态展示。
- AI 生成内容必须可追踪来源、任务、时间和失败原因。
- 岗位、测评、学习、画像之间的数据链路要保持可解释。
- 产品文案要避免夸大联网和 AI 结果的确定性。
